## Changes from the plan, and why

- **Two-phase write with recovery.** The plan called for an idempotency test; the first implementation passed a weaker version and still produced a duplicate in the crash-between-apply-and-commit case. Fixed by recording each write immediately (`syllabot record`) and having the next `plan` commit any uncommitted run from those records. T2 now covers the crash case explicitly.
- **Pending removal counted once per day, not per run.** "Two consecutive successful reads" is read as two different days, so a retried routine the same night cannot confirm a deletion by itself.
- **Partial readings.** Email is a partial source: it can move or add, never remove. A page that fails while an email succeeds is `source_failed` (update still allowed), distinct from `unreadable` (everything blocked).
- **Change statements beat stale pages.** When one source says "moved from X to Y" and the other still shows X, the change wins and the provenance records the stale page. Any other disagreement goes to review.
- **Not-read vs unreadable.** A course with no reading in a targeted run (owner resolving one item) is listed in one line as "not read", not as unreadable.
- **Zero-install path.** The engine has no dependencies so the playbook uses `git clone` + `python3 -m syllabot.cli`; pip is optional. Removes a failure mode from T7.
- **Bot name.** "Syllabus" used throughout as the working name; Registrar/Section/Proctor remain drop-in alternatives (profile only).
